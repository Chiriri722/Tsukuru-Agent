# Feature Specification: 번역 적용 무결성과 검증

**Feature Branch**: `chore/hardening-integration` (feature: `003-translation-validation`)
**Created**: 2026-09-13
**Status**: Ready for implementation
**Input**: Daybreak 후속 D21 P0–P2 개선, 브랜치 정리, 안내서에 따른 실제 내부 검증기 테스트.

## User Scenarios & Testing

### User Story 1 - 실패해도 작업본 보존 (Priority: P0)
번역자는 사전 적용이나 재삽입 실패 후에도 이전 작업을 그대로 이어갈 수 있다.
**Independent Test**: 후속 파싱 오류, 취소, 출력 설치 실패를 유발하고 기존 파일 바이트를 비교한다.
**Acceptance Scenarios**:
1. Given 기존 작업본과 Completed, when 사전 적용 뒤 재삽입 실패, then 모든 이전 작업과 원본이 보존된다.
2. Given 유효한 사전과 사용자 지정 출력, when 적용 성공, then 번역 작업본과 출력이 함께 반영된다.

### User Story 2 - 번역 손상과 검증 범위 확인 (Priority: P0)
번역자는 제어코드 손상, 새 빈 값과 깨진 문자를 공개 전에 발견하고 최종 출력의 적용 위치를 확인한다.
**Independent Test**: 같은 손상을 patch, 사전, 수동 Extract, 서비스 경로에 전달하고 쓰기 전 거절을 확인한다.
**Acceptance Scenarios**:
1. Given 원문과 매핑, when 제어코드/인수/자리표시자 손상 또는 새 빈 값/U+FFFD 입력, then 상대 파일과 ID가 있는 오류를 받는다.
2. Given 정상 번역과 원문 결함, when 적용, then 정상 escape와 원문 유지가 가능하고 새 손상만 차단한다.
3. Given 부분 출력, when 최종 검증, then 변경하지 않은 Backup과 합쳐 구조 및 실제 적용값/허용 범위를 검사한다.
4. Given 토큰이 일치하지만 의미만 뒤바뀐 번역, when 검사, then 의미 품질을 자동 통과로 표시하지 않는다.

### User Story 3 - 모아서 진단하고 실제 작업 검증 (Priority: P1)
번역자는 모든 사전 해시 충돌과 메시지 문맥 진단을 한 번에 받고 실제 작업팩에 같은 검증을 사용한다.
**Independent Test**: 다중 충돌, 여러 메시지 블록, AppleDouble 후보가 있는 합성/실제 복사본을 검사한다.
**Acceptance Scenarios**:
1. Given 여러 오래된 사전 대상, when 적용, then 전체 충돌 수와 상한 있는 파일/ID 목록을 받고 변경은 없다.
2. Given 메시지 여러 줄, when 괄호 검사, then 같은 페이지/이벤트/들여쓰기/메시지 블록에서만 연속성을 판단한다.
3. Given 인명·크레딧·의도한 원문 유지, when 언어 잔존/괄호 진단, then 감수 필요와 예외 근거를 구분한다.
4. Given AppleDouble 후보, when 추출/검증, then 데이터로 파싱하지 않고 원본 보관/무결성 기록은 유지한다.

### Edge Cases
- 빈 사전 값은 기존처럼 건너뛴다. 원래 빈 값/원문 그대로 보존은 새 손상이 아니다.
- 미지의 플러그인 명령과 인수는 보존한다. 의도한 괄호 표현 변경은 감수 진단에 근거를 남긴다.
- manifest 없는 GUI 작업본, 실행 파일 없는 portable 작업본, 별도 볼륨 출력도 구분한다.
- 일본어 0개/해시 재구축/구조 통과는 의미 정렬이나 실제 게임 실행의 증명이 아니다.

## Requirements

### Functional Requirements
- **FR-001 (D21-01)**: 사전 수정부터 출력 설치까지 실패/취소 시 작업본·출력·원본·Backup을 보존한다.
- **FR-002 (D21-02)**: 모든 RPG 수정 진입점에서 원문 출처와 제어 토큰/새 빈 값/U+FFFD를 검사한다. 검사 불가를 성공으로 표시하지 않는다.
- **FR-003 (D21-03)**: 공개 전에 최종 구조·실제 적용값·허용 위치 밖 변경을 검사한다. JSON/YAML/플러그인/외부 메시지/GUI 경로를 포함한다.
- **FR-004 (D21-04)**: 충돌은 결정적 순서로 전체 수, 최대 100개 상세, 생략 수를 반환하고 기존 오류 코드를 유지한다.
- **FR-005 (D21-05)**: 메시지 문맥과 일본어 잔존을 감수 진단으로 제공하고 의미/실게임 판단과 구분한다.
- **FR-006 (D21-06)**: AppleDouble을 RPG 파싱 후보에서 제외하며 원본 복사와 파일/크기 제한 범위는 유지한다.
- **FR-007 (D21-07)**: 오류에 확인 가능한 상대 파일/bucket/ID/dataPath만 보충하고 번역 전문은 노출하지 않는다.
- **FR-008 (D21-08)**: 각 회귀와 최종 필수 검증, 안내서 기반 실제 복사본 내부 검증을 기록한다.
- **FR-009**: 모든 기존 브랜치 변경을 대조·보존해 통합하고 불필요한 작업 브랜치를 정리한다.

### Key Entities
- 원문 결합: 상대 원본 파일, 번역 위치, 추출 구간, 확인된 원문.
- 번역 진단: 검사 종류, 상태, 심각도, 상대 파일/ID, 예외 또는 감수 근거.
- 적용 묶음: 작업본, 매핑, 검증된 출력과 실패 시 복구할 이전 버전.

## Success Criteria

### Measurable Outcomes
- **SC-001**: 실패/취소 회귀에서 기존 파일 변경 0개, 부분 출력 0개.
- **SC-002**: 제어코드/인수 손상, 새 빈 값, U+FFFD 합성 사례를 모든 적용 경로에서 차단하고 정상 대조군을 보존한다.
- **SC-003**: 다중 충돌 수가 정확하며 감수 결과를 자동 품질 보증으로 표시하지 않는다.
- **SC-004**: 최종 회귀와 실제 검증 결과에 재현 명령·범위·제약이 있다.

## Assumptions
- 사람의 의미 감수와 실제 게임 플레이를 자동 검사로 대신하지 않는다.
- 사용자 원본과 이전 번역은 보존하고 실제 검증 산출물은 Git에 포함하지 않는다.
- 새 외부 서비스/의존성을 추가하지 않으며 기존 계약을 보존하고 필요한 진단만 더한다.
