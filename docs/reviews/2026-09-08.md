## R1 [P2] v1 manifest의 줄 매핑 누락을 patch 전에 거부해야 한다

**상태: 수정 전 main 및 통합 기준선에서 재현. 후속 통합 작업 트리에 수정 추가; main 미병합.**

- 통합 위치: `tsukuru-agent/src/cli/patcher.ts:96`, `src/core/contracts/schemas/v1/manifest.schema.json:30`
- main 위치: [patcher.ts](../../tsukuru-agent/src/cli/patcher.ts), 줄 95
- 호출 경로: `executeAgentRequest` → `dispatchOperation` → `handlePatch` → `applyPatches`

v1 manifest schema는 호환성을 위해 entry의 `id`, `extractFile`, `hash`만 필수로 둔다. 그러나 patch의 범위 검사는 `lineStart < 0`, `lineEnd > lines.length`, `lineStart >= lineEnd`만 비교한다. `lineStart`가 없으면 비교가 모두 false가 되고, `slice(undefined, 1)`로 원문 해시 검증까지 통과한다. 이어지는 `splice`는 교체 대신 첫 줄 앞에 번역을 삽입하고, 매핑 계산의 NaN은 JSON에서 null이 된다.

통합 브랜치의 실제 `extract` 결과를 v1로 지정하고 첫 entry의 `lineStart`만 삭제한 뒤 v2 patch 요청을 `executeAgentRequest`로 실행했다:

```json
{
  "extractedOk": true,
  "patchedOk": true,
  "error": null,
  "text": "Translated\nOriginal",
  "lineStart": null,
  "lineEnd": null,
  "originalScript": "Original[l]\n"
}
```

즉 원본 KS는 보존되지만 추출 작업본과 manifest가 손상되고 성공이 보고된다. 손상된/불완전한 legacy manifest를 전달하는 조건이 필요하다.

**개선 방향:** 읽기용 v1 호환성과 쓰기용 매핑 조건을 분리한다. patch 전 `Number.isInteger`와 존재·범위를 검사하고, 수정되는 파일의 재계산 대상 entry 전체를 검증한다. 누락된 lineStart/lineEnd, 비정수 값, 수정하지 않는 이웃 entry의 잘못된 매핑에 대해 `E_MAPPING_CORRUPT`와 모든 작업 파일 바이트 불변을 검증한다. 이번에는 수정 없이 재현과 다음 작업을 기록했다.

## R2 [P1] main의 추출 경로 검사는 중간 정션을 따라간다

**상태: main 재현, 통합 브랜치 동일 재현 차단.**

위치: [patcher.ts](../../tsukuru-agent/src/cli/patcher.ts), 줄 24–34.

`resolveExtractArtifactPath`는 `path.resolve`/`path.relative`로 문자열 경계만 검사한다. `Extract/linked`가 밖의 디렉터리를 가리키는 정션이면 manifest의 `extractFile: "linked/dialogue.txt"`가 통과하고 patch가 그 외부 파일을 읽고 교체한다.

모두 이번 작업 전용 임시 폴더 안에 만든 합성 디렉터리로 재현했다. main은 오류 없이 외부 모의 파일을 `original`에서 `translated`로 변경했다. 통합은 `E_MAPPING_CORRUPT`를 반환하고 외부 파일·TXT·manifest를 보존했다. 통합의 `src/core/pathSafety.ts` 및 batch write 경계 검사가 대응한다.

**조치:** main을 안전한 최신 실행본으로 안내하기 전에 통합의 경로 정책과 회귀를 포함해야 한다. 정션이 들어 있는 작업 팩을 처리할 수 있는 실제 파일 쓰기 경계의 문제다.

## R3 [P1] main의 patch는 여러 파일을 하나의 변경으로 되돌리지 못한다

**상태: main 재현, 통합 브랜치 동일 실패 주입 시 복구.**

위치: [patcher.ts](../../tsukuru-agent/src/cli/patcher.ts), 줄 147–154.

main은 `.extracteddata`, 각 TXT, manifest를 별도 `atomicWriteFileSync`로 순서대로 저장한다. 뒤쪽 파일 교체가 실패하면 앞쪽 파일의 교체는 유지되므로, 개별 파일의 원자성만으로 전체 작업을 보존할 수 없다.

합성 Tyrano 작업본에서 마지막 manifest 임시 파일의 rename에 한 번만 `EACCES`를 주입했다. main은 오류를 반환했지만 TXT가 `translated`, manifest는 기존 hash로 남았다. 같은 실패에서 통합은 TXT와 manifest 모두 원래 바이트로 복구했다. 통합 `src/core/atomic.ts:38`의 `atomicWriteFilesSync`는 staging·backup·rollback을 묶는다.

**조치:** main에 통합의 batch write를 포함하기 전에는 “patch 실패 시 전체 작업본 무변경”을 보장할 수 없다. 이 검증은 예외 발생 복구이며 OS 강제 종료·전원 장애까지 검증한 것은 아니다.

**조치:** main의 GUI 계획 T001–T003을 신규 작업으로 다시 시작하기 전에 통합 구현과 이미 존재하는 회귀를 사용한다.
